First tagged release of voitta-gateway.

## In the image

`ghcr.io/voitta-ai/voitta-gateway:0.1.0` (linux/amd64) ships:

- Signal messaging (signal-cli, native build)
- Slack messaging and Slack calls (browser join page)
- Phone calls through Telnyx
- the service (REST API and event stream); library mode is in the Python package

## Not in the image: Signal voice calls

Signal voice calls are experimental and are **not** in the default image. They need
`signal-call-tunnel`, and the pinned tunnel ref does not compile against RingRTC 2.72 or later,
which is the floor for CVE-2026-113380. RingRTC is not downgraded to make it build.

- `adapters.signal.calls` defaults to `false`, and the example config leaves it off.
- Setting it to `true` with the default image does not work: signal-cli has no tunnel to start,
  so incoming Signal calls are not answered. Signal messaging is unaffected.
- The `with-signal-calls` build target (`docker build --target with-signal-calls`) adds the
  tunnel once a ref that builds against RingRTC >= 2.72 is pinned.

## Defaults that changed before this release

- Groups (Signal groups, Slack channels) are closed unless listed under `conversations`.
- `policy.inbound_allowlist` is empty: unknown senders are held until listed or approved.
- `send_read_receipts` is off.
- Account strings in the config are stripped of invisible Unicode format characters.
- FastAPI and uvicorn are in the `service` extra; the image installs it.
