Documentation only. No code changed since v0.2.0, so the API, the media protocol and the consumer contract are all unchanged, and nothing needs doing on upgrade. The image is `ghcr.io/voitta-ai/voitta-gateway:0.2.1` (linux/amd64); it is rebuilt from the same sources as `0.2.0` rather than retagged, so its bytes differ while its behaviour does not.

## An opening section for a reader who arrives cold (#19)

The file opened on the transport table, which answers "what does it speak" before "what is this and should I care". A reader who had not already decided to use the gateway had nowhere to start.

- **The problem it absorbs, stated first.** Being reachable on Signal, on Slack and by telephone means owning a signal-cli daemon exclusively, a Socket Mode websocket, and a telephony provider's call-control and media protocol -- three identity models and three sets of failure modes, none of them specific to the program being reached.
- **Who it is for, and who it is not for.** Any long-running program that people should be able to reach the way they already talk to each other. Not a bot framework and not an agent: the gateway holds no conversation state beyond routing and the event log, renders no Markdown, splits no messages, and decides nothing about what to say.
- **A pointer to the part most readers arrive needing.** Several programs sharing one account is the common case, so the opening links straight to [Several agents on one account](../../README.md#several-agents-on-one-account) rather than leaving it to be found.
