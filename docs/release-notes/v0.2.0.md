Several agents can now share one Signal account or Slack app, each seeing only the traffic meant for it, and Signal history keeps who a message named.

Everything since v0.1.0 (PRs #6 to #20). The image is `ghcr.io/voitta-ai/voitta-gateway:0.2.0` (linux/amd64).

## Signal history keeps its mentions (#20)

On Signal a mention is one U+FFFC in the text, and who it names travels beside it in `mentions`. The gateway recorded the text for history but not the list, so a message naming two people came back as a sentence with two holes, and a consumer could not tell an unresolved mention from someone typing a placeholder.

- `GET /v1/conversations/{id}/history` items carry `mentions` beside `parts`, in the same shape as on `message.received`.
- Edits keep them in step. An edit's own mentions replace the old ones, including for a held sender's message edited before approval, and `message.edited` now carries them.
- A delete clears them with the text.
- `null` means none were recorded. That covers messages received before this version, and messages sent through the API, whose mentions are in `parts[].mentions`.

The change is additive: a consumer that ignores the field behaves as before.

## One account, several agents (#6, #15, #16, #17)

- **`conversations` maps a group to the consumers that serve it.** The first consumer is the default addressee. The label doubles as a send alias (`to: {conversation: label}`), so group ids stay in `gateway.yaml`.
- **Events carry `addressed_to`, and the stream delivers each event only to that consumer.** Admin tokens see everything. The addressee is chosen in this order:
  1. the consumer whose message is being quoted, reacted to or edited;
  2. otherwise, one whose name is said in the text;
  3. otherwise, the conversation's default.
- **Slack threads and DMs follow whoever last posted.** A Slack thread goes to the consumer that posted last in it. A DM goes to the consumer that last sent into it, else to the adapter's `direct_consumer`.
- **A consumer acts only in conversations it serves.** It sends, reacts and reads history there, and edits or deletes only its own messages. A send into an unlisted group is 403 for every non-admin.
- **Optional per-consumer label** prefixed to the consumer's text.
- **Signal DMs: one conversation per person.** A DM started by number and the replies that come back by account id are one conversation, re-keyed to the account once the person answers. A recycled number therefore cannot land a new owner in the old owner's DM.
- **Quote routing skips send-only consumers.** A quote of a consumer that does not read messages, such as a digest poster, falls through to one that does. Reactions, edits and clicks on its posts still reach it.
- **`GET /v1/conversations`** lists the groups a token serves, by label, with channel, consumers and default addressee. Group ids are never returned.
- **`/help`** is answered by the gateway itself. It lists the agents serving the conversation, each with a new consumer `about` line and how to reach it. `/help <name>` goes to that agent so it can describe itself.

## Signal groups (#14, #18)

- **`groups: names`.** A listed group's message also reaches a serving agent when it says that agent's name. A name inside a URL, path, #tag or hyphenated word does not count. `mention` stays the default.
- **`admit: members`** on a conversation lets every member's message through while the group is closed: no group link, and only admins can add members. Openness is re-read every 30 s in the background. A group that is open, unread, or read more than 90 s ago falls back to the allowlist. Signal only.
- **`GET /v1/conversations/{label}/members`** returns a group's members (account id, admin, self, and `person_id`/`agent` from `persons`; never a profile name) and whether the group is open, with the reasons.
- **`persons` entries take `agent: true`**, so a consumer can tell other agents apart from people.

## The consumer contract (#7, #10, #12, #13)

- **The gateway neither renders Markdown nor splits messages.** Text parts take `styles: [{start, length, style}]` in UTF-16 code units. Channels without styles (Slack) answer 422 `unsupported`.
- **Signal has a size limit.** A send over 2000 UTF-8 bytes is 422 `too_long`, and a consumer label counts toward it.
- **Outbound Signal mentions.** Put one U+FFFC in the text and list `{id, start, length: 1}` on the text part. Each mention is validated, and a bad one is 422 `bad_mentions` rather than tagging the wrong person.
- **Inbound Signal events** carry the sent `timestamp` and `mentions`, each mention marked when it is this account.
- **Signal history.** Signal has no history API, so `GET /v1/conversations/{id}/history` is served from the gateway's own record. The record holds:
  - the messages it delivered as events (no held senders, no unaddressed group chatter);
  - released held messages;
  - its own sends.

  Edits and deletes keep the record current.
- **Deleted messages can't be edited**: a deleted message is 409 `deleted` on edit.
- **Held messages track the sender's changes.** A held sender's edits and deletes change or drop the held message.
- **`POST /v1/messages` takes `wait_s`** (up to 30). The call then answers 200 once the platform has the message, 502 `send_failed` if refused, or 202 if still in flight. A retry with the same `idempotency_key` waits on the same message. A key whose message no longer exists is 409 `message_gone`.
- **`person_id`** is also on `message.held` and every `message.status` event.

## Privacy and logs (#11)

- **Account numbers and ids are kept out of the logs.** Neither our own lines nor signal-cli's output and errors (scrubbed) contain the account number or ACI.
- **Uvicorn access logs are off.** They recorded query-string tokens.
- **Raw Signal envelopes are deleted once processed.** Rows left by v0.1.0 are deleted at startup.

## Signal voice calls (#9)

The experimental `with-signal-calls` build target now builds `signal-call-tunnel` against RingRTC 2.74.0, above the CVE floor, for linux/amd64 and arm64. A live Signal call has not been verified. The default image still has no tunnel, and `calls: false` stays the default.

## Upgrading from v0.1.0

- **Event delivery narrowed.** `message.status` and `operation.*` events now go only to the consumer that sent the message. The gateway's own sends, and their events, go to admin tokens only. With no `conversations` map and no `direct_consumer`, inbound routing is otherwise unchanged.
- **New column, no action needed.** The database gains a column through the existing additive migration.
- **Example config key renamed.** The person in the example config is now `p_owner`; only copies of the example are affected.
- **Licence.** The repository is now AGPL-3.0.
